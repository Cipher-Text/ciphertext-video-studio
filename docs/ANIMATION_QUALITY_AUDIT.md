# Animation quality audit

Audit date: 2026-11-11. Scope: existing Remotion scene layer, preset catalog, editor gallery, storyboard schema, preview, and render metadata. This is a technical and visual audit; it is not a factual approval of any documentary script or licensed asset.

## Existing pipeline

`src/animations/catalog.json` describes reusable motion templates. `src/animations/catalog.ts` maps legacy `animationConfig.mode` values to preset IDs. `src/video/sceneRegistry.tsx` dispatches an allow-listed renderer. `src/video/MasterDocumentary.tsx` owns camera movement, captions, sequence duration, narration audio, and `TransitionSeries`; `src/video/metadata.ts` calculates output dimensions and frame counts. The API stores catalog/quality metadata in SQLite, while renderer code stays in the application bundle. Catalog entries are not standalone rendered animation-video records. A storyboard scene stores an optional `animationPresetId` and per-scene settings; an uploaded `videoAsset` is a separate user-provided media clip.

The gallery preview (`PresetPreviewVideo`) creates a six-second, 360×640 synthetic scene and calls the same renderer registry used by project scenes. It supplies preset title, brand, camera movement, and intensity; it does not supply project narration, attached footage, `mapData`, or `comparisonData`. Preview and export share renderer code, but not all scene inputs. Applying a preset writes its ID and camera/settings onto a selected project scene; it does not generate or bind an MP4 animation asset.

## Findings and replacement plan

| Family / example | Audit finding | Replacement / remaining limit |
|---|---|---|
| Battlefield opening and engagement (`battlefieldAnimations.tsx`) | The older stage built terrain, tanks, smoke, and firing from flat SVG paths. Tank geometry was generic and could imply a specific vehicle model. | The main treatment uses a generated reconstruction plate, camera push/pan, haze, deterministic dust, kinetic title, and a visible “historical illustration · not archival footage” label. A scene image can replace the default plate. The gallery preset does not animate a tank independently; `AnimatedTank` and `TankMovement` are exported legacy components and are not wired into the active preset renderer. `videoAsset` does not replace the plate in this battlefield mode. Exact PT-76/M24 motion still needs reviewed, rights-cleared art or a sourced reconstruction.
| Infantry advance/contact (`genericAnimationScenes.tsx`) | Older renderers used stick figures and fixed contact marks. | Current illustrations use the local reconstruction plate; route overlays draw only scene `mapData`. Empty route input does not show a route. No people, weapon detail, or casualty animation is currently rendered. These are motion templates, not a video-clip library.
| Campaign map | The earlier reusable map renderer embedded fixed place names, coordinates, and a generic route. | The current `mapData` renderer uses scene-supplied relative schematic points/routes; `campaign-map` uses supplied GeoJSON. The Garibpur example stores its labels and illustrative route in that scene's data and cites the MP-IDSA map. Gallery map previews have no case data and show a source-required state. The UI has no dedicated `mapData` editor; add it through project JSON. The legacy `HistoricalMapScene` fallback still contains abstract decorative strokes, so use sourced map renderers for factual geography.
| KaloKhata records and funds | Hard-coded record cards/nodes repeated, and generic labels could imply real entities or a real transaction. | Added configurable allegation/status labels and source indicators; generic funds-flow remains explicitly conceptual. Added restrained status comparison and relationship-map templates with source-required labels. Real nodes still require reviewed scene data and legal status.
| Delta Signal weather | Rain, water, and storm visuals are deterministic geometry, not driven by observed weather inputs. The storm renderer draws a fixed path. | Treat rain/water backgrounds as illustration only. The fixed storm path is not an observed track even though its footer asks for a source. `comparisonData` renders user-provided series, but has no dedicated UI editor and its optional lower/upper interval values are not drawn. A data-bound storm-track renderer, station/location editor, uncertainty intervals, and data-entry UI remain future work.
| FactLens, Open Care, CipherText Labs | Those brands previously relied mainly on general placeholders; there were no dedicated gallery templates. | Added brand-specific editorial headline/claim-context, health-process/awareness, product-showcase, and system-architecture treatments. Schematic medical/software content is marked as such; screenshots and reviewed copy remain the path to publication-quality specificity.
| Camera and scene pacing (`MasterDocumentary.tsx`) | Many scenes defaulted to a linear zoom, and a per-scene alpha fade ran even across cuts. This repeated motion and softened scene starts. | Camera interpolation now uses in/out cubic easing; transition animation owns the transition. Camera direction and strength are editable separately from the scene preset. Rendered movement remains deterministic.
| Transition quality | Existing pipeline already uses Remotion `TransitionSeries` fade and wipe with overlap-aware frame accounting. | Kept the official compatible `@remotion/transitions` package; did not add Lottie, Three.js, or R3F because they do not materially improve these media-led 2D scenes on the target Mac.
| Typography / safe areas | Several fixed SVG font sizes and long copy could wrap poorly across portrait, landscape, and square. Bengali depended on system fallback fonts. | New title treatment uses clamped sizing, line-height, overflow wrapping, and mobile-safe margins. Bengali font stack now prefers macOS Kohinoor/Bangla, then Unicode fallbacks. The project does not bundle a licensed Bengali font file; verify fonts on the final render host.
| Preview/export consistency | Gallery previews do not load a complete project scene. | Preview uses the same allow-listed renderer as export, but builds a six-second, 360×640 synthetic scene with preset title and generic brand/default props. Project narration, media, and structured map/chart inputs are absent. Camera/intensity controls preview global motion only. Binding applies a preset reference/settings to a scene; no separate MP4 is created. Human frame review is still required.

## Preset contract and compatibility

Every catalog entry carries renderer/version/brand plus required and optional inputs, asset requirements, camera and motion defaults, transition/atmosphere/text treatment, supported aspect ratios, preview settings, render-cost estimate, and quality criteria. SQLite persists that metadata in an additive table. This describes renderer templates; it is not an animation MP4 inventory. Renderer keys remain allow-listed; JSON contains references/settings rather than executable code. Existing `videoAsset` upload, trim, and framing supports scene media independently.

`animationPresetId` takes precedence over legacy `animationConfig.mode`. Legacy modes remain accepted and are routed to the compatibility renderer when no explicit preset ID is present. Optional `mapData` and `comparisonData` are additive; old storyboard JSON remains valid.

The gallery's optional project-scene selector is the current binding workflow. It stores `animationPresetId`, `camera`, and `animationConfig.settings` on the chosen scene. There is no save-to-animation-file, generated MP4 clip catalog, or `mapData`/`comparisonData` form in the current UI.

## Quality gates and limits

- Typecheck and the existing unit suite are required after implementation. E2E, build, and real renders are listed in the mission brief and are run separately; successful tests do not establish professional visual quality.
- A real 18-second Garibpur portrait MP4 rendered successfully at 1080×1920 / 30 fps with Remotion Chrome for Testing and one render worker: `examples/rendered/animation-quality/garibpur-portrait.mp4`. The render completed all 540 frames. Landscape/square and six-brand MP4 checks remain pending: Chromium's subsequent macOS process launch failed with `MachPortRendezvousServer ... Permission denied` in this sandbox. `ffprobe` is not installed here, so the clip metadata still needs an external probe and human frame review.
- Render representative landscape and square Garibpur scenes and one short real render per brand pack; inspect contact sheets before making visual-quality claims.
- Run layout/source checks for missing data, frame size, safe areas, citations, and blank output. Automated checks cannot assess historical truth, Bengali typography aesthetics, edit rhythm, or whether a scene feels premium.
- No generated plate is archival footage or source evidence. Do not add unit markings or casualty depictions without reviewed references and rights.
- No third-party runtime packages were added. The generated battlefield plate is a project-local illustrative asset; it must retain the visible reconstruction label.
