# Animation quality audit

Audit date: 2026-11-11. Scope: existing Remotion scene layer, preset catalog, editor gallery, storyboard schema, preview, and render metadata. This is a technical and visual audit; it is not a factual approval of any documentary script or licensed asset.

## Existing pipeline

`src/animations/catalog.json` describes scene treatments. `src/animations/catalog.ts` maps legacy `animationConfig.mode` values to preset IDs. `src/video/sceneRegistry.tsx` dispatches an allow-listed renderer. `src/video/MasterDocumentary.tsx` owns camera movement, captions, sequence duration, narration audio, and `TransitionSeries`; `src/video/metadata.ts` calculates output dimensions and frame counts. The editor stores optional scene references/settings in the existing storyboard JSON. The API stores preset metadata in SQLite, while renderer code stays in the application bundle and rendered MP4s stay on disk.

## Findings and replacement plan

| Family / example | Audit finding | Replacement / remaining limit |
|---|---|---|
| Battlefield opening and engagement (`battlefieldAnimations.tsx`) | The old stage built terrain, both tanks, smoke, and firing from flat SVG paths. Tank geometry was generic and looked toy-like; its labels could imply exact models. | Primary treatment now uses a media-led, generated reconstruction plate, restrained push/pan, scrim, depth haze, deterministic dust, kinetic title, and a persistent “historical illustration · not archival footage” label. Supplied local image/video can replace the plate. Exact vehicle identity is not inferred from the generated silhouette. An authentic PT-76/M24 depiction still requires a reviewed licensed asset or expert-signed reconstruction.
| Infantry advance/contact (`genericAnimationScenes.tsx`) | Stick figures slid across flat fields and a modulo flash created a repetitive loop. | Replaced with a photographic reconstruction backdrop and source-driven route annotations. It draws no people, insignia, weapon detail, or invented route when the storyboard has no map data.
| Campaign map | Old `AnimatedBattleMap` embedded fixed place names and coordinates; generic users could inherit Garibpur facts. The generic route map also used an abstract route that could be mistaken for evidence. | Legacy map layout now reads optional `mapData`; new `campaign-map` uses supplied GeoJSON. The Garibpur example carries its schematic labels/route as scene data, cites the MP-IDSA map, and says “not to scale” and “illustrative.” Empty scenes show a data-required state. GeoJSON projection is real coordinate data; relative `mapData` points are explicitly schematic.
| KaloKhata records and funds | Hard-coded record cards/nodes repeated, and generic labels could imply real entities or a real transaction. | Added configurable allegation/status labels and source indicators; generic funds-flow remains explicitly conceptual. Added restrained status comparison and relationship-map templates with source-required labels. Real nodes still require reviewed scene data and legal status.
| Delta Signal weather | Rain dots and water shapes animated without measured input; the storm path was a fixed path. | Existing single-series treatments remain visually labeled as illustration and require source/time/unit. Added a two-series chart template that renders only supplied values and shows source/period/units. Missing data produces a requirement state, never synthetic values. Station coordinates, uncertainty bands, and multi-series editing UI remain to be completed.
| FactLens, Open Care, CipherText Labs | Those brands previously relied mainly on general placeholders; there were no dedicated gallery templates. | Added brand-specific editorial headline/claim-context, health-process/awareness, product-showcase, and system-architecture treatments. Schematic medical/software content is marked as such; screenshots and reviewed copy remain the path to publication-quality specificity.
| Camera and scene pacing (`MasterDocumentary.tsx`) | Many scenes defaulted to a linear zoom, and a per-scene alpha fade ran even across cuts. This repeated motion and softened scene starts. | Camera interpolation now uses in/out cubic easing; transition animation owns the transition. Camera direction and strength are editable separately from the scene preset. Rendered movement remains deterministic.
| Transition quality | Existing pipeline already uses Remotion `TransitionSeries` fade and wipe with overlap-aware frame accounting. | Kept the official compatible `@remotion/transitions` package; did not add Lottie, Three.js, or R3F because they do not materially improve these media-led 2D scenes on the target Mac.
| Typography / safe areas | Several fixed SVG font sizes and long copy could wrap poorly across portrait, landscape, and square. Bengali depended on system fallback fonts. | New title treatment uses clamped sizing, line-height, overflow wrapping, and mobile-safe margins. Bengali font stack now prefers macOS Kohinoor/Bangla, then Unicode fallbacks. The project does not bundle a licensed Bengali font file; verify fonts on the final render host.
| Preview/export consistency | Preset preview had its own composition framing and generic text overlays, so controls could overlap renderer footers. | Preview invokes the same allow-listed renderer and supports camera/intensity controls; it is isolated from project save state. Export uses the same scene registry. Human frame review is still required.

## Preset contract and compatibility

Every catalog entry carries renderer/version/brand plus required and optional inputs, asset requirements, camera and motion defaults, transition/atmosphere/text treatment, supported aspect ratios, estimated render cost, preview settings, and quality criteria. SQLite persists that contract in an additive table. Renderer keys remain allow-listed; JSON contains references/settings rather than executable code.

`animationPresetId` takes precedence over legacy `animationConfig.mode`. Legacy modes remain accepted and are routed to the compatibility renderer when no explicit preset ID is present. Optional `mapData` and `comparisonData` are additive; old storyboard JSON remains valid.

## Quality gates and limits

- Typecheck and the existing unit suite are required after implementation. E2E, build, and real renders are listed in the mission brief and are run separately; successful tests do not establish professional visual quality.
- A real 18-second Garibpur portrait MP4 rendered successfully at 1080×1920 / 30 fps with Remotion Chrome for Testing and one render worker: `examples/rendered/animation-quality/garibpur-portrait.mp4`. The render completed all 540 frames. Landscape/square and six-brand MP4 checks remain pending: Chromium's subsequent macOS process launch failed with `MachPortRendezvousServer ... Permission denied` in this sandbox. `ffprobe` is not installed here, so the clip metadata still needs an external probe and human frame review.
- Render representative landscape and square Garibpur scenes and one short real render per brand pack; inspect contact sheets before making visual-quality claims.
- Run layout/source checks for missing data, frame size, safe areas, citations, and blank output. Automated checks cannot assess historical truth, Bengali typography aesthetics, edit rhythm, or whether a scene feels premium.
- No generated plate is archival footage or source evidence. Do not add unit markings or casualty depictions without reviewed references and rights.
- No third-party runtime packages were added. The generated battlefield plate is a project-local illustrative asset; it must retain the visible reconstruction label.
